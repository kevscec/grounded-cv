# 05 — Projects

One entry per significant project. With a single employer this section is how breadth becomes
visible, so make the entries visibly different in *kind*, not three views of one job.

Give each a stable ID (`P1`, `P2`, …).

---

## P1 — [Name, described by what it does]

**Ownership:** built it / co-owned it / contributed to it — be exact · **Tier:**

**The problem.** In business terms, not technical ones.

**What this person did.** Distinguish personal authorship from what others built. This is where
attribution is decided, and getting it right here means every downstream document inherits it.

**Technologies.** And what was non-obvious about using them here.

**Outcome.** With metric IDs from `08_IMPACT_LEDGER.md`.

**The story worth telling.** The one detail that makes this memorable in an interview —
usually a thing that went wrong and what changed afterwards.

**Confidential?** If yes, note what must be translated before external use.
